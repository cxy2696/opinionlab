# 数学模型 / Math model

> **一分钟版本**
>
> - `q > 0` 控制跟随多数的强度：`q = 1` 是线性 Voter，`q → ∞` 趋向多数锁定，`q → 0+` 忽略多数有多大。
> - `time_to_consensus = -1` 表示**删失**（窗口内未形成多数），不是发散。
> - 95% 区间是副本均值的 Student-*t* 区间；`R < 30` 只应作方向性参考。
> - 这是情景推演，不是因果识别。

这份文档是 OpinionLab 模型的规范定义，代码与测试以它为准；README 只做摘要。每条公式都对应到一个函数，
避免某个引擎悄悄偏离另一个引擎。

## 1. 符号与假设

- 超图 `H = (V, E)`：`V` 是节点（人/账号/部门），`e ∈ E` 是群体互动场景（话题、群聊、会议），`|e| ≥ 2`。
- 节点权重 `α_j ≥ 0`：非负影响权重。来源包括 `uniform`（全 1）、`engagement`（接入图上的每节点互动量）、`centrality`（入射超边度数）与 `custom`（显式映射）。`max` 归一化把最大值缩放到 1；整体缩放会在从众映射中消去。
- 观点取值 `X_i ∈ {0, …, K−1}`；默认 `K = 2`。
- 时延 `L_i ≥ 0`：两次更新之间的最小间隔；`T_i` 是节点 `i` 上次改变立场的时刻。
- 决策规则 `decision_rule ∈ {stochastic, argmax, threshold}`。

自定义权重允许零值：零权重节点在加权计数中不发声。若某条超边的总权重为零，它没有可用信息，
引擎回退到均匀分布并记录 `zero_denominator_edges` 警告。负权重会被拒绝：它会让 `S_x` 为负，
使分数次幂 `q` 无定义。

## 2. 超边上的加权分布

对超边 `e` 和立场 `x`：

```
S_x(e) = Σ_{j∈e} α_j · 1(X_j = x)
```

`S_x` 是加权计数，不是归一化比例。权重尺度会在下一步消去，因此只有相对大小有意义。

## 3. 非线性从众映射

```
p_x(e) = S_x(e)^q / Σ_u S_u(e)^q          (q > 0)
```

当 `q > 0` 时，超边中不存在的立场满足 `S_x = 0`，概率为零。若整条超边总权重为零，引擎取
`p_x = 1/K`。`q = 0` 被拒绝：`q → 0+` 的极限是在**出现过的立场**上均匀，但 `q = 0` 的精确值依赖
`0^0` 的约定；按 NumPy 的约定会把质量分给未出现的立场。

| 情形 | 行为 |
|---|---|
| `q → 0+` | 在超边中出现过的立场上均匀；忽略多数有多大 |
| `q = 1` | 线性 Voter：概率正比于加权占比 |
| `q → ∞` | 质量集中到 `argmax_x S_x(e)`；并列时均分 |

实现：`hnle/core/kernel.py::conformity_probabilities`。

## 4. 节点聚合与更新

节点 `i` 的入射超边集合记为 `E_i`。把每条边的概率向量聚合为 `p_i = A_{e∈E_i} p(e)`。聚合方式 `A` 为：

- **`mean`**（默认）：入射分布的算术平均。它是凸组合，当 `|E_i| = 1` 时退化为 `p(e)`，且与超边顺序无关。
- **`size_weighted`**：以 `|e|` 为权的凸组合；大群体权重更高。
- **`max`**：逐元素取最大后再**归一化**为和为 1。它是对“最强群体说了算”的启发式，不是凸组合，
  也不能解释为群体意见的平均；归一化才使它成为概率分布。

随后：

- **就绪条件**：`t − T_i ≥ L_i`。未改变立场的节点在下一步仍然就绪；改变立场的节点被封锁 `L_i` 步。
- **随机规则**（默认）：`X_i(t+1) ~ Categorical(p_i)`。
- **argmax 规则**：`X_i(t+1) = argmax_v p_i(v)`；并列时取最小立场编号。它是论文公式 (3) 的确定性版本。
- **threshold 规则**：仅当最可能立场比当前立场**严格更可能**，且其概率不低于 `τ` 时切换；否则保持当前立场。
  并列时保持现状。因此该规则同时需要当前立场与 `p_i`。

离散引擎在步末原子写回。事件引擎使用同一套时钟规则；整数时延下两者逐步一致
（`tests/test_engine_equivalence.py`）。

## 5. 引擎

- **CSR 稀疏引擎（默认）**：同步步进。所有就绪节点从步首状态更新。这是参考语义。
- **事件引擎**：只支持整数时延。改变立场的节点在 `L_i` 步后再次到期；未改变立场的节点在下一步到期。
  每个整数步都记录序列，因此可与 CSR 序列直接比较。连续时延由 CSR 引擎处理；事件引擎在参数校验阶段拒绝它。
- **二元特例。** 当 `K = 2`、权重为正且时延有限时，状态是吸收态当且仅当超图的每个连通分量内部一致。
  在非连通图上，过程会冻结成分量意见的“马赛克”，因此即使所有分量都已冻结，人群层面的 `absorbing`
  仍可能为假。请把 `absorbing` 与 `runaway` 当作人群层面的标签；图碎片化时要检查分量结构。
  证明与推论见 HNL 修订版（`Hypergraph-Nonlinear-Latency-Voter-Model` 仓库的 `docs/MODEL.md`）。

## 6. Monte Carlo 估计与置信区间

同一 `ModelSpec` 下独立运行 `R` 个副本，得到指标 `Y_1, …, Y_R`：

```
mean = (1/R) Σ_r Y_r
var  = (1/(R−1)) Σ_r (Y_r − mean)^2
CI95 = mean ± t_{0.975, R−1} · sqrt(var / R)
```

实现：`hnle/mc.py`（Welford 在线更新，避免大样本数值漂移）。

**严谨性说明**：

- 该区间是 Student-*t* 区间，不是正态近似。`R ≥ 30` 时 `t ≈ 1.96`；`R` 更小时区间更宽。
  `R < 30` 会给出 underpowered 警告。
- 同时报告多个指标时，不对“所有指标同时覆盖”作保证；不要挑一个显著的结果讲故事。
- 副本必须独立同分布；共享随机流会低估方差，引擎为每个副本用 `SeedSequence` 分流。
- 时间到共识等指标存在**删失**（窗口内未达到多数）。`time_to_consensus = −1` 记录该情况；
  报告需说明删失比例，不能把“未达到”当作 0。旧的 `runaway` 布尔量只是该情况的别名，不是“发散”的证据。

## 7. 可复现与不变量

- 超边先排序，重复节点编号会被拒绝，重复超边会被合并；浮点求和顺序固定，节点置换不改变结果。
- 每个副本的初始化、时延、决策使用独立的 `SeedSequence.spawn(3)` 流，避免流间耦合。
- 指标使用 float64；测试统一用 `numpy.testing.assert_allclose`，禁止 `==`。
- API 与报告只输出群体统计量，任何单节点轨迹在边界被拒绝。

## 9. 假设与失效边界

- 拓扑与权重来自给定数据；模型不推断真实关系，也不建模推荐算法、媒体议程或线下行为。
- 参数 `q`、时延与初始分布必须外部标定；未标定时，结论只具方向性。
- 模型是**情景推演**，不是因果识别：改变参数后的差异不能直接解释为真实干预的因果效应。
- 任何个人层面的预测、画像或打分都不在模型承诺范围内，也违反产品红线。
